> 面向 WPF 工具「数据验证排查」页面（`DataValidationPage`），数据库类型选 **PostgreSQL**。
> 本套数据已用项目真实的 `DdlParser / InsertStatementParser / FieldMatcherService / ValidationEngine` 跑通验证，覆盖完整类型与校验规则。

## 二、目标表结构 `t_data_valid_demo` 与校验规则对照

| 列名 | PG 类型 | 归一化类型 | 约束 | 主要可触发规则 |
|------|---------|-----------|------|----------------|
| id | integer | Integer | 非空、主键 | 主键定位 |
| patient_uuid | uuid | Guid | 非空 | GUID 格式错误、必填为空 |
| patient_name | varchar(50) | String | 非空 | 字符超长、必填为空 |
| age | smallint | Integer | 非空 | 整数格式错误、整数溢出（-32768~32767）、必填为空 |
| birth_date | date | Date | 可空 | 日期格式错误 |
| created_at | timestamp | DateTime | 可空 | 日期时间格式错误 |
| last_updated | timestamptz | DateTime | 可空 | 日期时间格式错误（**需带时区偏移**） |
| start_time | time | Time | 可空 | 时间格式错误 |
| zone_time | timetz | Time | 可空 | 时间格式错误（**需带时区偏移**） |
| is_active | boolean | Boolean | 非空 | 布尔格式错误、必填为空 |
| amount | numeric(10,2) | Decimal | 可空 | 数值格式错误、数值精度溢出 |
| ratio | numeric(8,4) | Decimal | 可空 | 数值格式错误、小数位溢出 |
| record_count | bigint | Long | 可空 | 整数格式错误、长整数溢出 |
| ext_data | json | Json | 可空 | JSON 格式错误 |
| settings | jsonb | Json | 可空 | JSON 格式错误 |
| raw_tags | text[] | String* | 可空 | 见下方注释 |
| duration_interval | interval | **Unknown** | 可空 | **未识别类型（警告）** |
| zjb_note | varchar(100) | String | 可空 | 自动映射：**前缀剥离**（匹配源列 `note`） |
| dmmc | varchar(100) | String | 可空 | 自动映射：精确匹配 |

\* **关于 `text[]`**：当前 `DdlParser` 会把 `TEXT[]` 的方括号当作空参数组解析，从而归一化为 `text`（String），不会触发“未识别类型”。这是工具现状（边界行为）。本表用 `interval` 类型专门演示“未识别类型”规则（`SchemaNormalizer` 未收录的 PG 类型都会归为 Unknown，仅做非空校验并给出警告）。

## 四、向导操作步骤

1. **进入**：数据工具 → 数据验证排查；数据库类型下拉选 **PostgreSQL**。
2. **步骤① 结构输入**：粘贴 `01_建表DDL` 全部内容 → 点「解析 DDL」。应提示“DDL 解析成功，共 18 个字段”，自动识别为 PostgreSQL 并回填表名 `t_data_valid_demo`。
3. **步骤② 数据输入**：粘贴 `02_测试数据INSERT` 全部内容 → 点「解析 INSERT」。应提示“INSERT 解析成功，共 21 行”。
4. **步骤③ 字段映射**：
   - 观察自动匹配结果：除 `patient_uuid`（UUID，需人工确认）外，大部分字段为“精确”（100%），`zjb_note` 为“前缀剥离”（90%，匹配源列 `note`）。
   - 手动处理 `patient_uuid`：映射方式选“源字段映射”，来源列选 `patient_uuid`（或点「忽略全部 UUID」），并点「确认全部」（或逐行确认）。
5. **步骤④ 校验**：点「开始校验」。核对摘要（约 20 项错误 / 1 条警告）与错误明细、错误类型环形图、按类型/关键字筛选、复制。
6. 点「导出报告」可生成包含摘要、错误明细、字段汇总的 Excel 报告。

## 五、扩展测试场景

| # | 场景 | 操作 | 预期 |
|---|------|------|------|
| ① | **必填未映射** | 回到步骤②，把 INSERT 字段列表中的 `age` 删除后重新解析 → 步骤③ 确认 → 校验 | 每行报“必填未映射：age”（错误） |
| ② | **固定值映射** | 步骤③ 将某可空列（如 `dmmc`）映射方式改为“固定值”，填 `demo` 并确认 | 该列统一用固定值参与校验，不再读取源列 |
| ③ | **忽略映射** | 步骤③ 将可空列（如 `raw_tags`）设为“忽略”并确认 | 该列不再校验，无相关问题 |
| ④ | **跳过格式错误** | 步骤④ 勾选“跳过整数格式错误 / 跳过 GUID 格式错误 / 跳过日期时间格式错误”再校验 | 对应格式类错误被抑制，但溢出类仍报告 |
| ⑤ | **忽略值** | 步骤④ 勾选“忽略指定实际值”，在列表中加 `UNKNOWN`（或从 id=21 的错误明细右键“加入忽略值”）再校验 | id=21 的 age 整数格式错误消失 |
| ⑥ | **主键定位与去重** | 步骤③ 主键1 选 `id`（可选再加 `patient_uuid`） | 错误明细显示“主键=id=xx”；错误计数按主键去重 |
| ⑦ | **自动匹配方式** | 可把源列名改成不同形态观察匹配：如目标 `birth_date` 源列写 `birthdate`（标准化）、`zjb_note` 源列写 `note`（前缀剥离）、源列含 `_dm/_id/_code` 等（语义） | 匹配方式与置信度变化；UUID 字段始终需人工确认 |
| ⑧ | **取消 / 截断** | 校验中点多行数据可点「取消校验」；或构造超大异常数据触发 10,000 条上限 | 状态栏提示“已取消”或“结果已截断” |

## 六、验证方式与覆盖范围

- 本套 DDL / INSERT 已通过项目真实解析器（`DdlParser`、`InsertStatementParser`）成功解析：**18 字段 / 21 行 × 19 列，解析零警告**。
- 已用真实 `ValidationEngine` 执行完整校验，逐条确认上表所有预期规则均被触发（含必填未映射演示）。
